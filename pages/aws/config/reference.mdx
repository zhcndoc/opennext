`open-next.config.ts` 中可使用的所有选项都将在此列出。这是可用于自定义构建的配置文件。
你可以查看 [完整示例](full_example) 以了解如何使用这些选项。

<br />

<Tabs.Tab>
  这里的服务器指的是所有不同的构建输出（Lambda、Node、Deno 等）。每个服务器都可以有自己的选项。这也包括一些只需要在构建时运行的服务器/函数。

每个服务器配置将在配置对象中拥有自己的键。以下是您可以配置的所有服务器：

- 默认服务器 - 键：`default` 这是默认服务器，类似于 open-next v2 中的 server-function
- 拆分服务器 - 键：`functions` 仅当您想将服务器拆分为多个服务器时使用。这是一个特殊情况，在此键下您将定义每个拆分的服务器。
- 外部中间件 - 键：`middleware` 如果您想将中间件与默认服务器或函数分开部署，可以使用此键。
- 重新验证函数 - 键：`revalidate` 这是一个特殊的服务器，将处理重新验证队列。
- 图片优化服务器 - 键：`imageOptimization` 此服务器将处理 `_next/image` 优化。
- 预热函数 - 键：`warmer` 此服务器旨在用作 lambda 函数的预热。
- 初始化函数 - 键：`initializationFunction` 这是一个特殊的服务器，将在构建时运行以初始化缓存。默认情况下，它只初始化标签缓存。

<Tabs items={['通用选项','默认服务器', '拆分服务器', '外部中间件','图片优化服务器', '重新验证函数', '预热函数', '初始化函数']}>
  <Tabs.Tab>
      所有这些服务器共享一些通用选项，您可以使用它们来自定义服务器。

      ### `minify`

      这将尝试压缩服务器的输出，包括 `node_modules`。它是一个布尔值，默认设置为 `false`。
      这可能会导致某些包出现问题，因此建议在部署之前使用此选项测试您的应用。

      我们可能不会修复与此选项相关的问题，因为它通常是特定于库的。

      ### `override`

      在这里您将能够覆盖服务器的某些部分。对于所有选项，您可以提供我们称为 `LazyLoadedOverride` 的内容，这是一个将返回覆盖内容的函数。有关示例，请参阅一些 [自定义覆盖](custom_overrides)。
      所有服务器都有一些您可以覆盖的默认覆盖。您可以 [在此处](https://github.com/opennextjs/opennextjs-aws/blob/5b314b13b2907a4510e7f0cca6959f8da4eab310/packages/open-next/src/types/overrides.ts) 查看类型。

      #### [`wrapper`](overrides/wrapper)

      这是服务器的入口点。
      请注意，仅更改此选项可能不足以使其在该平台上工作。这只是入口点，您可能需要更改服务器的其他部分才能使其在该平台上工作。

      可能的值有：`aws-lambda`、`aws-lambda-streaming`、`cloudflare-edge`、`cloudflare-node`、`node`、`express-dev`、`dummy` 或一个将返回包装器的 `LazyLoadedOverride`。

      #### [`converter`](overrides/converter)

      这是将用于转换服务器输入和输出的转换器。

      可能的值有：`aws-apigw-v2`、`aws-apigw-v1`、`aws-cloudfront`、`edge`、`node`、`sqs-revalidate`、`dummy` 或一个将返回转换器的 `LazyLoadedOverride`。

      #### `install`

      服务器的安装选项。用于安装额外的包。它是一个包含以下选项的对象。

      对于图片优化，默认情况下将安装 sharp

      ##### `packages` - 必填

      这是将在服务器中安装的包数组。它是一个字符串数组。
      在默认服务器（或拆分服务器之一）上安装内容可能需要在 Next 端进行一些额外配置以避免重复

      ##### `arch`

      这是服务器的架构。它是一个字符串，默认设置为 `x64`。

      可能的值有：`x64`、`arm64`

      ##### `nodeVersion`

      此选项将传递给 sharp 的 postinstall 脚本。它由 `node-gyp` 使用。

      ##### `libc`

      覆盖要安装的原生模块的 libc。

      可能的值有：`glibc`、`musl`

      ##### `additionalArgs`

      传递给安装命令 (npm install) 的额外参数。它是一个字符串，将附加到 `npm install` 命令的末尾。

      以下是如何在默认服务器函数上安装带有 ARM64 架构的 sharp 的示例：

      ```ts
      import type { OpenNextConfig } from '@opennextjs/aws/types/open-next';
      const config = {
      default: {
        install: {
          packages: ['sharp@0.33.5'],
          arch: 'arm64',
        },
      },
      } satisfies OpenNextConfig;

      export default config;
      ```

  <Tabs.Tab>
      ### `runtime`

      服务器使用的运行时。默认服务器仅支持 `node` 或 `deno`。

      `edge` 运行时仅可用于拆分服务器，并且每个服务器仅支持一条路由。
      这也要求路由使用 Next.js 的 edge 运行时。

      可能的值有：`node`、`deno`、`edge`

      ### `placement`

      确定服务器将部署在哪里的选项。是在单个区域还是在边缘的多个区域。

      此选项对构建输出没有任何影响，但只是指示 IAC 工具知道在哪里部署服务器。

      可能的值有：`regional`、`global`

      ### `experimentalBundledNextServer`
      将 Next 服务器打包到单个文件中。
      这会导致打包体积小得多，但在某些情况下可能会破坏功能。

      此选项已弃用，不适用于 Next 14.2+。

      ### `override`

      对于默认服务器和拆分服务器，除了通用选项中的 `override` 外，您还可以使用以下选项：

      #### [`incrementalCache`](overrides/incremental_cache)

      添加覆盖默认 s3 缓存的可能性。用于 fetch 缓存和 html/rsc/json 缓存。

      可能的值有：`s3`、`s3-lite`、`multi-tier-ddb-s3`、`fs-dev`、`dummy` 或一个将返回增量缓存的 `LazyLoadedOverride`。

      #### [`tagCache`](overrides/tag_cache)

      添加覆盖默认标签缓存的可能性。用于 revalidateTags 和 revalidatePath。

      可能的值有：`dynamodb`、`dynamodb-lite`、`fs-dev`、`dummy` 或一个将返回标签缓存的 `LazyLoadedOverride`。

      #### [`queue`](overrides/queue)

      添加覆盖默认队列的可能性。用于 ISR 重新验证请求。

      可能的值有：`sqs`、`sqs-lite`、`dummy` 或一个将返回队列的 `LazyLoadedOverride`。

      #### [`proxyExternalRequest`](overrides/proxy_external_request)

      添加覆盖外部请求默认代理的可能性（即 next config 外部重写或中间件重写）。用于外部中间件或服务器函数之一。

      可能的值有：`node`、`fetch`、`dummy` 或一个将返回代理的 `LazyLoadedOverride`。默认是 `node`

      #### [`cdnInvalidation`](overrides/automatic_cdn_invalidation)

      添加覆盖 CDN 失效覆盖的可能性。用于 `revalidatePath()`、`revalidateTag()` 和 `res.revalidate()` 的按需失效。

      可能的值有：`cloudfront`、`dummy` 或一个将返回 invalidatePaths 的 `LazyLoadedOverride`。此覆盖默认禁用。

  </Tabs.Tab>

  <Tabs.Tab>
      每个拆分服务器都将具有与默认服务器相同的选项。除此之外，您可以使用以下选项：

      ### `routes` - 必填

      在这里您应该指定所有想要使用的路由。
      对于 app 路由，您应该使用 `app/${name}/route` 格式，对于页面使用 `app/${name}/page`。
      对于 pages，您应该使用 `page/${name}` 格式。

      例如：
      ```ts
      routes: ["app/api/test/route", "app/page", "pages/admin"]
      ```

      ### `patterns` - 必填

      指定将用于匹配路由的模式。它是一个字符串数组。
      它需要兼容 cloudfront。

      例如：
      ```ts
      patterns: [
      // 这将匹配所有以 /api/ 开头的路由
      "/api/*",
      // 对于单个路由，这将只匹配 /page
      "/page",
      ]
      ```

这些选项位于配置对象的顶层。

### `buildCommand`

这是用于构建您的 Next.js 应用的命令。默认情况下，它尝试找到您的包管理器并将运行 `npm run build`。它支持 npm、pnpm、yarn (不支持 pnp) 和 bun。

如果您想指定不同的命令，可以在此处进行。

### `appPath`

Next.js 应用源代码根目录的路径。此路径相对于当前 process.cwd()。

默认情况下，它设置为 `.`

### `buildOutputPath`

来自 `buildCommand` 选项的构建输出目标文件夹的路径（将包含 `.next` 和 `.open-next` 文件夹的路径）。此路径相对于当前 process.cwd()

默认情况下，它设置为 `.`

### `packageJsonPath`

Next.js 应用的 package.json 文件的路径。此路径相对于当前 process.cwd()。

### `edgeExternals` - 高级用法

如果您在某处使用 edge 运行时（无论是在中间件还是在函数中），我们会编译 2 个版本的 open-next.config.ts 文件。一个用于 node 运行时，一个用于 edge 运行时。

此选项允许您指定用于编译 open-next.config.ts 的 esbuild 中 edge 运行时使用的外部依赖
如果您仅在 node 中使用一些自定义覆盖，这特别有用

### `dangerous`

这些是您只有在知道自己在做什么的情况下才应该使用的选项。如果未正确使用，它可能会在运行时破坏您的应用。
这也是您可以找到一些实验性功能的地方。

---

#### `disableTagCache`

这将禁用标签缓存。如果您只使用页面路由，可以安全地禁用它。
它用于 `revalidateTag` 和 `revalidatePath`。
它是一个布尔值，默认设置为 `false`。

#### `disableIncrementalCache`

这将禁用增量缓存。通常不建议这样做，因为这对于 ISR **和** SSG 路由以及 fetch 缓存都是必要的。
它是一个布尔值，默认设置为 `false`。

#### `enableCacheInterception` - 实验性

这将启用缓存拦截。它将允许您直接在 OpenNext 路由层内拦截缓存系统，并直接从缓存提供页面，而无需经过 `NextServer`。

如果缓存拦截失败，请求将照常转发给 `NextServer`。

#### `headersAndCookiesPriority`

用于确定哪个头部或 cookies 具有优先级的函数。
默认情况下，中间件头部和 cookies 将覆盖处理程序头部和 cookies。

这在每个请求后执行，且在 next config 头部和中间件执行之后。
以下是如何使用它的一个非常简单的示例：

```ts
// 在这种情况下，如果请求以 /api 开头，中间件头部和 cookies 将优先，否则处理程序头部和 cookies 将优先
headersAndCookiesPriority: (event) => {
  if (event.rawPath.startsWith('/api')) {
    return 'middleware';
  }
  return 'handler';
},
```
